MirrorTone Lab · Public Research Overview

Whitepaper｜公開研究概述

從人的主體性出發，說明 MirrorTone、WorkNet 與 MTEL 如何把高能力 AI 協作轉成可授權、可查證、可校正、可回退、可完成判定的工作結構。

Why this matters / For whomPublic ResearchResearch Repo ↗
公開定位：這是一份 public-safe research overview，不是完整內部規格、runtime dump、產品保證或第三方認證。它從現役工作網抽出對外可說、且不依賴內部控制碼才能成立的穩定結構。

1｜問題不是 AI 能力不夠，而是能力如何進入真實世界

當 AI 只回答問題，錯誤常停留在文字層。當 AI 開始使用工具、跨步驟工作、讀寫外部系統、長期保留狀態、影響判斷或交付成果，失敗的型態就改變了：它可能做了沒有取得授權的事、把舊資料當成現況、把工具成功當成任務完成、在錯誤後只改表面結果卻保留錯誤依賴，或讓人類仍然簽名卻已失去判斷來源的可見性。

MirrorTone 因此不把「更會做事」當作唯一目標。它研究的是：如何讓強能力保持積極，同時讓人的主體、授權、證據、責任與修正能力仍然成立。

2｜三個層次：MirrorTone、WorkNet、MTEL

MirrorTone

上游研究層。關心人的主體性、認知、差異、責任、接收與校正能力，以及不同形式智能如何長期共存而不被壓成同一種東西。

WorkNet

工作與治理環境。把 task、target、authority、evidence、memory/context、tools、readback、rollback、handoff 與 completion 放進同一條可追蹤工作鏈，讓能力可以前進，但不能自行取得更高權限。

MTEL

工程轉譯層。把可公開的治理命題轉成較薄、可編譯、可測試、可回放的工程表示，並把複雜度下放到 schema、trace、tests、evaluator、profile 與 pack，而不是把所有東西塞回單一 prompt。

Public Research

對外證據面。Frontier Signals、Public Notes、研究案例、公開 Repo 與工程候選分別承擔觀測、命題、方法、證據與可檢查實作，不互相冒充成熟度。

3｜五個公開治理問題

MTEL 對外仍維持五個最短入口。它們不是整個 MirrorTone，而是任何 agentic system 都可以被追問的公共檢查面：

  • Capability — 系統實際能做什麼？
  • Authority — 誰授權它做，以及權限邊界在哪裡？
  • Evidence — 什麼可定位證據支持目前狀態、判斷與主張？
  • Rollback — 發生錯誤或越界後，錯誤與其後果如何被撤回、隔離與修復？
  • Completion — 誰有資格判定工作確實滿足完成條件？

Readback 是貫穿這五項的連接組織：工具成功、檔案存在、搜尋命中、頁面更新或模型自述都不是完成證明；系統必須重新讀回正確目標，確認實際狀態與主張一致。

4｜Current state 不是「搜得到」，而是「讀回正確的東西」

現役工作網把 currentness 與 retrieval 明確分開。搜尋、記憶、mount、歷史 context 或相似檔名可以協助定位，但不能自行把某個候選升格成「現在的事實」。要承擔 current-state claim，必須先確認目標身分，再讀到足以支持該命題的內容。

這個差異看似細小，實際上決定了系統會不會把過期版本、近名文件、舊持倉、舊規格或錯誤頁面當成現在。對長時間、多工具、多專案環境而言，readback 不是附加驗證，而是把世界重新接回模型的動作。

5｜Evidence 有管轄範圍，不是拿到新資訊就重寫一切

新證據只應改變它真正支持的 target、layer 與 scope。較低層的具體事實，不會自動否決較高層的結構；較高層的抽象模型，也不能反過來抹掉已確認的具體事實。跨層改判需要明確的 dependency、causal 或 semantic bridge。

這使校正不再等於「整套翻案」。如果只證明一個局部 binding 錯了，就修正那個 binding 及其依賴；沒有被證偽的狀態繼續有效。這同時降低兩種風險：一種是錯誤擴散，另一種是為了修一個小洞而摧毀仍然有效的工作脈絡。

6｜真正的 rollback 是重建可信狀態，不是道歉或改一行字

當一個承重 state、source、relation 或 target 被新證據否定，工作網不允許它繼續正常傳播。正確動作是隔離受污染的 dependency cone，回到最近可信狀態，取得 fresh evidence / readback，重新綁定必要關係，再驗證是否可以恢復長鏈。

因此 rollback 的單位不是情緒，也不是單一輸出句，而是錯誤實際影響到的依賴範圍。如果一次 bounded recovery 仍出現同族 mismatch，就應停止繼續擴張，而不是靠更多文字把錯誤包起來。

7｜Autonomy 應該被保留，但不是黑箱化

MirrorTone 不把治理理解成每一步都停下來請示。低風險、可逆、依賴關係清楚的步驟可以連續執行；真正需要重新收斂的是承重 hinge，例如外部寫入、路由或範圍改變、跨檔整併、結論升格、跨專案 handoff、高風險或不可逆動作，以及最後的 completion。

這是一種 bounded autonomy：能力與主動性可以在合法區間內高速運作，但每當系統準備跨越權限、證據、責任或不可逆邊界，就必須重新取得資格。治理的目的不是把強能力壓成被動，而是避免長鏈能力變成無法看見的自我授權。

8｜沒有合法下一步時，「不製造工作」也是治理

工作網把「缺口存在」與「現在就必須施工」分開。能力尚未建立、證據不足、材料仍在 watch、或某個想法值得研究，都不自動構成新增規格、PR、schema、evaluator 或治理任務的理由。

只有當現有治理確實無法處理一個可重現失敗，或使用者明確授權施工時，才進入最小、可驗、可退的修改。這使 NO WORK / WAIT FOR EVIDENCE 成為合法結果，而不是把 agent 的活動量誤當價值。

9｜從來源到執行體：不同成熟度不能混成同一層

現役工作網持續把 raw intake / mother source、freeze、transform / compile、validation 與 released execution surface 分開。Drive、working desk、live link、draft、patch 或漂亮的設計稿都不因存在而等於 runtime。

這條 lifecycle 邊界很重要，因為 AI 系統最容易出現的完成度幻覺之一，就是把「已寫出」「已整理」「已測一部分」「工具回傳成功」誤寫成「已部署／已驗收／已生效」。公開研究因此也刻意區分研究命題、工程候選、qualification evidence 與產品成熟度。

10｜人的主體性不是最後多按一次 Approve

人的主體位置不只是在流程最後保留一個批准按鈕。當 AI 長期參與資訊選擇、問題 framing、理由生成與方案比較時，真正需要保留的是 judgment provenance：這個判斷如何形成、哪些理由來自誰、哪些條件由誰設定、誰負責最後授權，以及修正後責任如何重新落位。

因此在共同施工中，人仍主導方向與最終授權；AI 可以是高能力共同施工者，也必須對自己的輸出、施工與錯誤負責。這不是把 AI 擬人化，而是避免用「人最後有按確認」掩蓋實際認知與責任鏈已經改變。

12｜目前不主張什麼

  • 不主張 MirrorTone 已解決一般 AI alignment 或 agent safety。
  • 不主張公開五問等於完整 incident-response、security architecture 或 production governance stack。
  • 不把內部 runtime、私人資料、未公開方法或未驗證工程面直接外倒。
  • 不把單一供應商自述、單一案例、單一 benchmark PASS 或工具成功升格為普遍有效性。
  • 不因研究公開就主張第三方認證、產品成熟度或完整 repo 再利用授權。
核心方向：MirrorTone Lab 要研究的不是如何把智慧約束成服從，而是如何讓強能力、真實差異、持續學習與彼此校正都能存在，同時不交出人的主體、證據、責任與回退能力。
